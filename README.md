# Aleatoric Luck

## Research overview

Aleatoric Luck studies how out-of-sample predictive performance changes with
the number of available training cases (\(N\)) and predictor variables
(\(K\)), and whether their contributions vary across outcomes, datasets, and
statistical models.

For each outcome and model, the analysis repeatedly selects
\(N\) training cases and \(K\) eligible predictor variables, estimates
data-dependent preprocessing within the selected training sample, fits the
model, and evaluates predictions on held-out cases. Here, \(K\) counts raw
predictor variables. Columns created from the same categorical variable are
selected together, while an explicitly declared missingness indicator counts
as a separate predictor.

## Running the analyses

Run all commands from the repository root. Python 3.11–3.14 is supported.

### 1. Create the environment

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e "NK_Grid[models,parquet,test]"
python -m pytest -q
```

### 2. Add the source data

Place the untracked source files at:

```text
SMR/data/private/asample2_withlag.csv

FFCWS/data/private/background.dta
FFCWS/data/private/train.csv
FFCWS/data/private/test.csv
```

These private inputs are excluded from Git.

### 3. Prepare the analysis data

Prepare and validate the analysis data:

```bash
python SMR/adapter/adapter.py
python FFCWS/adapter/adapter.py
```

Each command generates the analysis-ready tables and corresponding schemas for
its application. If an input is missing or a generated file fails validation,
the command stops before model fitting.

### 4. Review the analysis design

Review the resolved design before fitting any models:

```bash
aleatoric-nk-grid-panels --manifest SMR/panels.yaml --dry-run
aleatoric-nk-grid-panels --manifest FFCWS/panels.yaml --dry-run
```

The dry run reports the outcomes, models, \(N\) and \(K\) values, repeated
draws, and total number of analysis cells while leaving all models unfitted.

### 5. Run an analysis

Run one SMR outcome:

```bash
aleatoric-nk-grid-panels \
  --manifest SMR/panels.yaml \
  --only smr_hourlywage
```

Run one FFCWS outcome and predictor representation:

```bash
aleatoric-nk-grid-panels \
  --manifest FFCWS/panels.yaml \
  --only ffc_median_mode_gpa
```

Run every outcome and model in an application:

```bash
aleatoric-nk-grid-panels --manifest SMR/panels.yaml
aleatoric-nk-grid-panels --manifest FFCWS/panels.yaml
```

Results are written below `SMR/outputs/` or `FFCWS/outputs/`. The checked-in
panel specifications use the small `dev` setting by default. Review the
dry-run output before changing the analysis scale.

Full experiments are intended for a cluster. Submission, checkpoint recovery,
and resource settings are documented separately in the
[N-by-K implementation guide](NK_Grid/README.md). Data-specific preparation is
documented in the [SMR guide](SMR/adapter/README.md), the
[FFCWS guide](FFCWS/adapter/README.md), and the common
[adapter specification](Adapter/ADAPTER.md).

## Repository organization

```text
Aleatoric_Luck/
├── Adapter/      common requirements for preparing analysis data
├── NK_Grid/      implementation of the repeated N-by-K research design
├── SMR/          SMR data preparation and analysis specification
└── FFCWS/        FFCWS data preparation and analysis specification
```

The application directories share the same structure:

```text
<application>/
├── adapter/          data-preparation program, configuration, and tests
├── schema/           machine-readable analysis specifications
├── data/
│   ├── private/      source data; excluded from Git
│   └── ard/          generated analysis-ready data; excluded from Git
├── panels.yaml       outcomes, models, and N-by-K design
├── model_params.yaml
└── README.md
```

Schemas are generated by each application's adapter and are versioned because
they record the interpretation of the generated data. Source data,
analysis-ready data, and model outputs are excluded from version control.
