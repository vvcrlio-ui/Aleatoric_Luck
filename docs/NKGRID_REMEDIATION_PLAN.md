# NKGRID 修改方案与对抗性验收

状态（2026-09-07）：M1–M6 已有分批本地实现；对抗性验收部分完成。逐项证据与未验收项目见 [验收报告](NKGRID_REMEDIATION_ACCEPTANCE.md) 和 [机器可读记录](remediation_evidence/acceptance.json)。不得将实现完成解读为真实历史 GPA 下降、集群 OOM 或恢复协议已全部验收。

审查基线：`SMR&FFC`，提交 `d5df3df55e10bbce593f3fb8d5db7b10c550701d`。用户报告：FFC 的 GPA 在 N 超过约 200 后 Super Learner 表现下降，所指参数为 MLP 的 batch size；LightGBM/XGBoost 有 OOM，Slurm 计划准备较慢。

下列原始实施目标及验收门槛保留。实施从所列基线开始；MLP 默认仍为 auto。原始数据与既有结果未改写。已用新提供的 ICPSR Challenge 数据开展训练池内部 GPA 对照，但未收到历史结果、manifest 和原 OOM 单元的 Slurm 配置，因此尚不能复现用户所指历史现象。

### 实施中核对到的事实与最小修正

- `sampling_units()` 原来已将派生指示归属父变量；错误在请求构建和列宽估计等调用点，未重写 Adapter 筛选规则。补充规范父变量顺序，三种版本化表示仍均为 3400 个抽样单位。
- 原 `log2_size_grid()` 已有正确的精确数量生成逻辑，本次保持不变。容量检查针对显式输入及每个实际训练划分。
- 固定 LightGBM 4.6 的原生回归 CV 在 N 不能整除 5 时，使用前五个长度 `N // 5` 的随机块，余数行不进入 CV。M2 精确保留这一既有折定义；最终 fit 仍使用全部 N 行。不得在工程批次顺便换成另一种 5 折划分。M4 也保持折索引，仅改变折内预处理及分箱范围。
- M4 的完整管线 Ridge LOO 成本明显高于旧解析 RidgeCV；生产路径每折一次 SVD 共享原 alpha 网格，并通过逐 alpha 的独立 sklearn Ridge oracle 验证。未改成 5 折、未按 N 切换算法。
- 同一 snapshot 的恢复复用原本已由 `submit_flat_task_table.sh` 提供。M6 补计时和实际运行环境绑定，不新增缓存、不删除任务表、不省略每轮设计/WAL 索引。计时包含嵌套阶段，`.locked` 为锁内递归，不能将所有时间直接相加。
- 新运行采用算法身份 `nk-grid-v6-fold-local-1`、CellExecutionSpec 2、公共 serializer 3；旧 `r2_test`/`skill_score_pct` 含义不变。serializer 3 包含可选诊断 JSON 列。旧结果可单独解释，但旧 snapshot 不允许混入新运行。
- 实际环境绑定包括依赖版本和数值线程环境；planner/prep/worker/verify/close/finalize 的 Slurm 脚本统一声明单线程。手工调用 Python 入口也必须使用一致环境，不能通过移除校验规避不匹配。
- Windows 的独立数值验收绕过包的 eager POSIX 入口导入，未伪造 `resource`/`fcntl`。全引擎、锁、进程树及 Slurm 项仍需目标 Linux 实测，状态见逐项报告。

## 1. 从第一性原理确定修改标准

本项目需要估计：给定训练样本数 N、可用原始信息单元数 K 和训练算法时，样本外损失如何变化。计算实现必须忠实表达这一实验，而不能将实现边界误解释为社会现象。

由此得到六条不可妥协的条件：

1. **标签真实。** 结果中的 N/K 必须等于实际使用的训练行数/抽样变量数。编码列数另记，不能混用。
2. **训练信息边界明确。** 外部测试集不参与模型拟合、调参或默认参数选择；声称折内验证的步骤，其拟合统计必须仅来自该折训练数据。预先定义的特征宇宙另行声明。
3. **工程优化不暗改估计对象。** 降内存、缓存和调度优化，默认必须保持数据、折划分、参数选择规则和预测语义。无法保持时，拆成独立的方法变更。
4. **评分基准明确。** 原始损失与相对基准分数不是同一个量，不能通过更换分母掩盖小样本误差。
5. **实验一致与执行完整分别证明。** 相同配置哈希只能证明声明一致；不能证明使用了正确数据、产生了相同数值，更不能证明没有漏算、重复或损坏。
6. **结论可被反例推翻。** 验收必须主动攻击边界、错误输入、失败恢复和错误修复方案。成功跑通一个示例不等于通过。

最小修改规则：优先修复已有函数、复用现有数据契约和测试设施；一次提交解决一个可陈述的问题。不引入通用调度平台、通用CV框架、额外服务或数据库。不得借本次修改替换模型库、升级依赖、增加模型、改变研究结果变量或改写Adapter筛选规则。

## 3. 实施批次及边界

| 批次 | 实现内容 | 修改性质 | 明确不做 |
|---|---|---|---|
| M1 | 统一抽样单位、修复网格与容量检查、只读历史审计 | 正确性修复 | 不改抽样随机序列、K网格生成算法 |
| M2 | Boosting逐折回归CV、修正列宽与内存核算 | 优先保持数值语义的工程修复 | 不改折数、参数网格、模型精度或训练设备来规避OOM |
| M3 | Super Learner批量配置、定点诊断与训练池内对照 | 配置显式化；默认变化须有证据 | 不根据外部测试曲线选参数，不同时换优化器/网络结构 |
| M4 | 内折拟合预处理 | 单独的方法变更 | 不声称与旧结果数值等价，不顺便改Adapter特征筛选 |
| M5 | 明确评分列、添加MSE与分母、版本兼容 | 输出/指标契约变化 | 不静默改变旧列定义，不在本批实现幂律模型 |
| M6 | 计划阶段计时、相同实验恢复复用 | 调度优化 | 本期不删除任务表、不更换WAL协议、不支持跨不兼容版本恢复 |

M1首先实施。M2的旧方法等价验证必须在M4之前完成。M3可以先诊断，但新默认策略的结论需在M4之后再次验证。M5独立验证。M6先测量再改最慢且可局部优化的路径。

相比上一轮口头方案，本期主动收缩两项：不立即实施“无任务表调度”；不预先决定用完整批量替换MLP默认值。前者涉及恢复协议，后者尚无因果证据。

## 4. M1：保证N/K标记忠实于实际输入

### 实现内容

1. 用现有 `source_groups()` / `sampling_units()` 作为K定义的唯一来源。生产请求构建和引擎通过同一小型解析入口取得有效训练容量、抽样单位数及网格，不另写一套根据JSON条目数推断K的逻辑。
2. 在知道实际数据容量后、写入大任务表前，验证所有显式N/K：非布尔正整数、无重复、满足原有顺序契约、未超过容量。禁止先 `int()`、`set()` 或截断再声称输入合法。程序自身生成的规范网格与外部传入网格应有明确边界。
3. 内部划分若不同seed有效训练容量不同，按实际各seed验证；外部划分按该结果变量去除缺失结果后的训练行数验证。不能用原始表行数代替。
4. 在切片前和实际模型fit前保留廉价断言：实际行数=N、实际抽样单位数=K；K_expanded等于展开后的列数。此处不重复全表读取或哈希。
5. 增加只读历史审计入口，报告来源提交、网格、`K > n_features_total`、`N > n_train_total`、重复键及可用证据不足项。异常结果需隔离于后续分析；不自动改标签、合并或删除。

### 实现边界

不改变seed/draw派生、变量顺序、同一次draw内的嵌套抽样及现有 `log2_size_grid()`。错误的旧计划直接明确拒绝，不将K自动压到3400，因为那会改变实验设计并制造重复单元。历史标签错误也不能直接改成3400：模型随机种子可能已使用了错误K。

### 对抗性验收

| 编号 | 攻击输入/方法 | 必须观察到的行为 |
|---|---|---|
| A1 | 使用版本化的FFC三种表示定义；缺失指示含8053个分组 | 三者均解析为3400个抽样单位；保持相同seed/draw/K的源变量集合一致 |
| A2 | 一个父变量含值列和多个缺失指示，重排派生分组 | K不增加；派生列随父变量整体进入，比较基于规范源顺序 |
| A3 | N等于容量、容量+1；K等于容量、容量+1 | 边界合法；超界在plan写入/模型fit前失败，不能留下可提交的部分计划 |
| A4 | `True`、0、负数、1.5、NaN、重复值、错误顺序 | 违反契约的输入明确报错；不能隐式取整、去重或换序掩盖错误 |
| A5 | 结果变量缺失使训练池缩水；内部分类划分改变容量 | 按实际可用训练行数验证；测试集数量不能进入训练容量 |
| A6 | 直接调用执行入口，绕过生产请求构建器 | 最终执行仍拒绝N/K越界，证明验证没有只放在CLI |
| A7 | 合法旧设计在修复前后运行 | 源变量、样本、模型种子不变；预测满足同环境回归标准 |

反向检验：临时恢复 `len(sources)` 或移除执行层容量检查，A1/A6必须失败。若仍通过，测试无效。

## 5. M2：降低CV峰值内存，先保持旧方法

### 实现内容

1. 在现有两个回归封装内实现逐折生命周期，不增加通用CV抽象：构建一折数据与模型，保存验证指标曲线，释放对象，再处理下一折。
2. 保持每个模型原有折划分、seed、折数、损失定义和折间汇总方式。XGBoost保留现有显式折索引；LightGBM用与固定版本原实现一致的折索引。
3. 汇总每轮曲线后，复现旧规则选择统一轮数。LightGBM不能改成各折独立提前停止再平均轮数；必要时各折运行到原max_rounds，再按聚合曲线重放提前停止逻辑。额外计算时间必须报告。
4. CV对象释放后才开始完整训练重拟合。使用局部作用域/明确资源释放；若原生分配器保留内存导致进程RSS无法下降，再局部采用一折一子进程，不能仅凭 `del` 宣布内存修复。
5. 核对原实现与新实现的数据分箱、缺失值、参考Dataset/DMatrix及默认参数语义。若降低内存要求改变这些语义，标记为方法变化，不能冒称“完全等价”。
6. 将列宽计算改为按 `sampling_source` 汇总派生列。计划覆盖任意随机K子集时，用宽度最大的K个抽样单位之和作为列数上界；已知精确任务时可使用精确列宽。不能继续使用定义文件前K项。
7. 将内存模型中的常驻原始数据、训练/测试切片、预处理副本与模型内部内存分别说明。现有固定倍数公式只能作为估计，需真实进程树/Slurm cgroup峰值验证，不承诺数学上界。

### 实现边界

仅先替换独立LightGBM/XGBoost回归CV路径，不改分类固定轮数路径，不改Super Learner内LightGBM。保持5折、float精度和CPU计算方式；不得把降折数、改float32、采样训练数据、减少树数当成等价修复。

“各折模型不同时驻留”不等于“整个任务只占一份数据”。完整训练数据、测试矩阵、父子进程和库缓存均须计入。

### 对抗性验收

| 编号 | 攻击输入/方法 | 必须观察到的行为 |
|---|---|---|
| B1 | 同折索引、同seed的稠密/高维/含NaN/常数目标/最小合法N数据 | 逐轮曲线与旧CV对照；唯一最优时轮数一致，最终预测与指标满足预先声明容差 |
| B2 | 构造最佳轮数在第一轮、最后一轮、早停边界及并列最优的曲线 | 首次最优与提前停止规则匹配；不能平均各折最佳轮数 |
| B3 | N不能被5整除，且各折误差显著不同 | 严格保留原折权重/汇总方式；不能把平均RMSE换成汇总MSE后开根号 |
| B4 | 跟踪各折原生训练对象生命周期；在最宽矩阵测进程树峰值 | 同时存活的折训练上下文最多1个；报告CV及最终fit两阶段峰值 |
| B5 | 第3折抛异常、被杀或超时 | 不使用不完整曲线选择轮数，不写成功结果；错误进入既有失败处理 |
| B6 | K=25选择宽分类变量；K=3400使用缺失指示表示 | 宽度上界覆盖实际列数；后一例为16085列而非6713列 |
| B7 | 集群原失败单元，相同输入、CPU及内存上限 | 新实现完成；记录旧/新退出状态、总峰值和时长。缺少真实失败配置时，此项标记未验收 |

同环境确定性数据初始数值门槛：预测/曲线 `rtol=1e-7, atol=1e-9`，离散设计及无并列时选中轮数严格一致。并列或近似并列先用固定的曲线级用例验证规则，不能事后提高容差解释任意不同轮数。出现差异先定位，必要时将该修改转为版本化方法变更。

反向检验：重新保留全部折模型，B4必须失败；将轮数改为折最佳轮数的平均，B2必须失败。

## 6. M3：批量边界的诊断与最小修复

### 实现内容

1. 仅在Super Learner回归MLP增加批量配置，允许 `auto`、合法正整数及 `full` 策略。`full` 必须在每一次实际fit时使用该次训练行数，包含折内拟合与最终重拟合，而不是固定成外层N。
2. 参数通过现有model_params验证、模型构造和契约记录。配置字段需明确属于MLP，不复用引擎检查点 `batch_size`。兼容旧配置时默认仍为 `auto`；任何新默认值须单独提交。
3. 诊断仅对显式选择的少量单元启用，记录每折/完整fit的N、有效batch、MLP迭代与收敛、基模型OOF误差、集成系数和截距。不能把每个production单元都扩展成庞大模型日志。
4. 在FFC GPA固定表示、固定K和重复抽样上检查N=180、199、200、201、220、250、251、252、300。覆盖低K及较高K，使用同一随机排列的嵌套样本；保存原抽样与模型seed派生，不能暗改以追求曲线平滑。
5. 在训练池内部划分独立诊断验证集，对 `auto` 与 `full` 做成对对照。报告均值、分布和失败率，不只选一条改善曲线。外部测试集不参与选择默认策略。
6. 若batch变化不能解释下降，保持默认值，利用同一诊断检查基模型表现变化、未收敛或集成系数放大；不同时增加正则化、约束权重和调整学习率。

### 实现边界

N=201–250时完整fit每epoch有2批，5折中的fit通常仍有1批；此机制确定，但预测下降不是数学必然。`auto -> 200` 与原行为相同，不能作为修复。`full`是诊断候选，也不保证最优；固定epoch并不保证不同batch策略拥有相同优化步数，报告必须注明。

不要求预测能力随N单调上升。有限样本、优化随机性和嵌套抽样都可产生波动。Super Learner目前使用非负线性元模型但没有权重和为1的约束；这是需要记录的模型定义，本批不自动改成凸组合。

### 对抗性验收

| 编号 | 攻击输入/方法 | 必须观察到的行为 |
|---|---|---|
| C1 | 记录N=199/200/201/250/251/252的每个实际fit | `auto`复现边界；`full`每次fit均只使用一整批，不能把外层N误传给内折 |
| C2 | sklearn clone、折内训练、最终重拟合与序列化 | 批量策略没有丢失；诊断准确区分折内与最终模型 |
| C3 | 只改检查点batch_size或把auto改200 | 明确不能宣称MLP训练机制修复；数值应保持相应兼容行为 |
| C4 | 更改外部测试目标/预测文件 | 不影响批量策略选择、基模型拟合或集成权重 |
| C5 | 构造零信号、小N、大K及有强基模型差异的数据 | 不以提高分数作为硬性通过条件；检查有限输出、失败报告及诊断真实性 |
| C6 | M4实施后重复预先声明的训练池内对照 | 默认策略的依据仍成立，或撤回结论；不能沿用已过时的诊断结论 |

通过分两层：配置/诊断正确可先通过；“修复GPA下降”须真实成对实验支持。没有数据时不将后一层标记完成。

## 7. M4：内折预处理隔离

### 实现内容

1. 梳理一次fit中所有需要学习的统计：连续/分类缺失填补、无观测源处理、标准化及目标缩放。明确其是在Adapter、外层N子样本还是内折拟合。
2. 将现有类型感知预处理封装为最小的可克隆fit/transform对象，或在现有内折循环中直接复用同一fit/transform实现。以改动较小且不会重复维护规则的方式为准；不引入新的通用预处理框架。
3. 进入CV/stacking的输入需保留原始缺失状态。只在全N数据上填补后再套一层SimpleImputer，不能实现折内隔离。
4. 每折在训练侧拟合填补与缩放，再变换验证侧；最终在完整N上拟合并变换外部测试侧。分类源仍原子处理；派生指示仍属于父变量；折内全缺失源按现有先验/NaN契约处理。
5. MLP目标缩放同样置于折内；Lasso内部选择alpha不能继续接收已经全N标准化的数据；Super Learner OOF列必须由该折专属处理链产生。
6. Ridge不能简单保留“全N标准化 + RidgeCV解析LOO”并称其为完整管线LOO。先实现小规模显式LOO参考，保持既定alpha候选与评分规则；生产路径采用经参考验证的实现。若时间成本不可接受，单独提出折数/算法变更，不暗自将LOO换成5折或按N切换方法。

### 实现边界

FFC按预定义训练池建立的特征宇宙/筛选是当前Adapter契约。本批将其视为已声明的固定输入，不随内折重建词表或改变3400个源变量；因此CV结论以该特征宇宙为条件。外部测试集仍不能影响词表。

此批为方法变更，允许与旧预测不同，必须更新模型/算法身份。对原生boosting分箱等库内拟合步骤，明确折内数据构建范围；若相较M2的旧CV兼容实现发生变化，纳入本批变更说明。不得承诺“折内全部隔离”却只修复其中一层。

### 对抗性验收

| 编号 | 攻击输入/方法 | 必须观察到的行为 |
|---|---|---|
| D1 | 固定源宇宙和折索引，只把一个内折验证侧X改成极端值 | 该折训练侧填补/缩放统计及模型参数不变；预测值可因输入变化而变化 |
| D2 | 只改变一个内折验证侧y | 该折基模型/目标缩放不变；验证损失、最终alpha/集成权重可以改变，不能错误要求它们不变 |
| D3 | 外部测试侧X/y加入极端值 | 全部训练统计、调参结果、集成权重不变；测试预测或评分可以改变 |
| D4 | 内折训练全缺失、验证有值；训练缺某分类水平 | 严格复现类型/先验规则；不借验证侧补统计，不造成编码列错位 |
| D5 | 验证侧极端值使全N中位数明显偏移 | 能区分“真正折内填补”与“先全N填补再内折fit”的伪修复 |
| D6 | 小数据显式完整管线LOO与Ridge生产路径对照 | 每个候选alpha的折外预测/损失及选择规则匹配参考 |
| D7 | 无缺失但量纲极不均、目标离群的数据 | 仍能检测缩放/目标缩放泄漏；不能只有缺失值测试 |

反向检验：把填补或标准化移回全N，D1/D5/D7中对应测试必须失败。

## 8. M5：评分定义与幂律输入

### 实现内容

新增或明确下列输出：

| 字段 | 定义 |
|---|---|
| `mse` | 外部测试目标与预测的均方误差，不由四舍五入的RMSE反算 |
| `null_mse_train_mean` | 用当前N个训练目标均值预测测试集得到的MSE |
| `test_target_variance` | 测试目标绕自身均值的平均平方差，即ddof=0 |
| `skill_train_mean` | `1 - mse / null_mse_train_mean` |
| `r2_test_mean` | `1 - mse / test_target_variance` |
| `r2_test` | 旧兼容列，仍等于原来的训练均值skill，不悄悄重定义 |

现有 `skill_score_pct` 保持原定义。分母为0时相应新分数记NaN，不强制变成0或1；测试目标有效但为常数时MSE仍可输出。非有限预测仍进入失败诊断，不将其转换成可接受的零分。指标定义在manifest中版本化，并同步本地CSV、动态公共结果schema及合并验证。

### 实现边界

本批不拟合幂律、不报告不可约误差估计，不将 `1-skill_train_mean` 当原始误差。测试均值仅用于最终评价分母是合法评分定义，不能据此声称训练泄漏。历史无原始预测时不保证能重建所有新指标；可由未截断RMSE平方推算的历史MSE只能注明为派生值。

### 对抗性验收

| 编号 | 攻击输入/方法 | 必须观察到的行为 |
|---|---|---|
| E1 | test=[0,2]，训练均值2，预测=[2,2] | MSE=2，训练skill=0，测试均值R²=-1 |
| E2 | 完美预测、预测训练均值、预测测试均值、显著更差的预测 | 结果符合各自公式；不截断负分，不混入Pearson相关平方 |
| E3 | 常数目标、零分母、单测试样本、NaN/Inf预测 | 依明确边界返回NaN或失败；不能把未定义结果伪装成成功高分 |
| E4 | 对目标和预测同时平移/乘非零常数 | 两个相对分数按公式不变；MSE随倍数平方变化 |
| E5 | 同预测同测试集，仅改变训练均值 | MSE与r2_test_mean不变；skill_train_mean按其定义变化 |
| E6 | 新旧schema混合发布或恢复 | 契约不兼容时拒绝；旧列含义不变，旧结果仍可独立解释 |

独立oracle使用直接求和公式；不能只比较两个调用了同一评分helper的输出。

## 9. M6：以最小修改减少Slurm准备工作

### 本期实现

1. 先记录阶段级时间与数据量：输入校验/哈希、网格解析、任务枚举、SQLite唯一性检查、Parquet写入、各轮prepare的设计/WAL索引、最终核验。
2. 明确区分“新建独立实验”与“恢复同一实验”。恢复入口接受已有snapshot，验证契约和工件后复用同一任务表，不重新调用生产计划生成器。
3. 优先接通或修正现有恢复路径；已有功能满足需求时只补文档和回归测试，不再开发缓存层。
4. 保留现有AnalysisContract/DynamicExecutionContract划分、租约、原子发布、WAL和重复键核验。实际依赖版本/环境标识须记录并在新契约下校验；requirements文件相同不代表运行环境相同。
5. 若测量表明瓶颈在每轮全量索引，不将“复用plan”宣称为已解决全部耗时。再根据测量提出独立的增量索引方案，需新的恢复一致性审查。

### 不在本期实现

不删除任务表、不引入整数索引生成器替代它、不任意更改worker数绕过执行契约、不跨输出目录复用活动运行状态，不用mtime/文件大小代替内容校验。无任务表方案只能作为后续设计，必须先证明任务枚举、断点状态及最终完整性与原系统等价。

修改worker数或资源可能需要新执行契约；同一分析身份不意味着旧激活状态可以直接重用。CPU线程配置若影响数值，也不能简单归类为“与实验无关”。内容哈希本身仍要读取内容；本期不承诺所有校验变为常数时间。

### 对抗性验收

| 编号 | 攻击输入/方法 | 必须观察到的行为 |
|---|---|---|
| F1 | 恢复同一snapshot，监测生产计划生成器调用 | 任务表字节不变；不重新枚举/写入全量plan |
| F2 | 修改一个数据值但保持文件大小/mtime；修改模型参数、源顺序或seed | 相关内容/语义校验失败；不能错误命中复用 |
| F3 | 不改requirements，仅换实际依赖版本 | 新契约识别环境变化；拒绝混算或明确建立新版本运行 |
| F4 | 两个提交者同时恢复同一输出 | 现有租约仍阻止重复发布；没有部分激活状态可被当作成功 |
| F5 | 在写任务表、激活、WAL提交和发布边界中断 | 可按现有协议恢复，或明确拒绝不完整工件；不丢已提交成功结果 |
| F6 | 配置完全相同，但删一条成功结果/复制另一条补足总行数 | 完成性核验失败，证明不是只看哈希和总行数 |
| F7 | 用相同任务集改变任务分配顺序；尝试直接修改worker数 | 合法重排不改变数值设计；未建立合法执行契约的资源变更被拒绝 |
| F8 | 相同硬件、输入、文件系统，分别记录冷启动与恢复 | 分阶段报告时间；恢复无全量plan构建工作，不以冷缓存/热缓存差异冒充收益 |

## 11. 对抗性审查如何执行

### 三层证据

1. **结构与数学层：** 使用手算指标、独立枚举、极端类型/容量输入。测试oracle不得复用被测函数计算期望值。
2. **行为与故障层：** 在实际入口检查预处理隔离、批量传播、折对象生命周期、契约拒绝以及中断恢复。mock只用于证明调用边界；不能替代真实训练/原生内存验证。
3. **真实工作负载层：** 固定FFC GPA表示、K、seed/draw、依赖和资源，重放下降区间与OOM单元；记录可复现命令及工件身份。没有数据或集群时标为“未验收”，不能降格成通过。

### 主动构造错误实现

在临时副本中逐一引入以下错误，验证相关测试会失败，再丢弃副本：

- 将抽样变量数改回分组数；删除执行层上限检查。
- 把逐折实现改回持有所有fold；把统一轮数改成各折最佳轮数平均。
- 把MLP策略固定成200；让clone丢弃策略参数。
- 在CV前全N填补/缩放；在OOF预测中使用完整N拟合的基模型。
- 交换两个评分分母；把负分截成0。
- 复用仅依据mtime；移除任务键完整性检查，只核对输出行数。

这些不是要求引入新的mutation-testing依赖；采用受控临时修改即可。每个错误应至少被一个独立测试抓住。抓不住时优先修验收，而不是增加与实现同构的断言。

### 测试运行与结果记录

从各批次直接相关测试开始，变更触及共享引擎后再运行现有回归集合：

```bash
python -m pytest -q NK_Grid/tests SMR/adapter/tests FFCWS/adapter/tests
```

默认排除的slow测试需按B4/B7/F8选取运行，不能把普通pytest通过当作内存/集群验收。新增有意义的用例放在现有主题测试中，缺少合适位置才新增测试文件。涉及POSIX锁、Slurm与原生内存行为的验收在目标Linux环境完成，Windows下阅读/小例不能替代。

每项验收记录：编号、基线/候选提交、输入与环境指纹、命令、实际结果、预期结果、通过/失败/未验收、输出位置。数值容差与性能比较设置在查看候选结果前确定。正常CV差异、未复现与缺少数据必须保留，不能只展示有利seed。

## 12. 交付与完成标准

交付物：分批代码提交；A–F验收记录；只读历史结果审计；GPA批量对照；Boosting内存/时长对照；Slurm阶段计时；版本兼容说明和恢复操作说明。

实施所需真实材料：发生下降的GPA结果及评分列、三种表示中的具体版本、K范围与seed/draw；原运行manifest/提交/依赖版本；OOM单元与Slurm命令、内存限制、退出记录；plan及prepare阶段日志。能独立完成的代码和合成验收先做，缺少这些材料只阻止对应真实验收结论。

完成条件不是“测试全绿”或“曲线更好看”，而是：

- 已知定义错误有修复，且反例不能穿过实际执行入口；
- 纯工程修改有语义保持证据，方法变化有独立版本与解释；
- GPA下降和OOM分别有真实验证结论，或明确保留为未解决，不能混称完成；
- 恢复优化未削弱结果完整性和失败恢复；
- 未通过项、未验收项、历史受影响范围均可见。
